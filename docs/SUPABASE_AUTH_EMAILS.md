# Supabase Auth Email Templates

The production magic-link email should clearly mention the app. Supabase Auth owns the actual email delivery, so the repo tracks the approved copy and HTML template while the project setting must be applied in Supabase.

## Magic Link Template

Subject:

```text
Your Photo Gratitude Journal sign-in link
```

Required Supabase variables:

- `{{ .ConfirmationURL }}` for the one-time sign-in URL.
- `{{ .Email }}` for the recipient email.

The source of truth for the current HTML template is `web/src/lib/auth-email-copy.ts` in `supabaseMagicLinkTemplate`.

## Apply In Supabase

Dashboard path:

1. Open the Journal Supabase project.
2. Go to Authentication > Emails / Email Templates.
3. Edit the Magic Link template.
4. Set the subject to `Your Photo Gratitude Journal sign-in link`.
5. Paste the HTML body generated by `supabaseMagicLinkTemplate("https://journal-gginestas-projects.vercel.app")`.
6. Send a test magic link from the production login page.

Management API option:

- Use the Supabase Management API only with a project-scoped management token in a private terminal or trusted automation.
- Do not commit management tokens, service-role keys, database passwords, or generated API requests containing secrets.
- After applying, test a production magic link and confirm the subject names Photo Gratitude Journal and the CTA lands on `/auth/callback`.

## QA

- Send a production magic link to a real tester email.
- Confirm the subject mentions Photo Gratitude Journal.
- Confirm the button text says `Open Photo Gratitude Journal`.
- Confirm the fallback URL includes the Supabase confirmation URL.
- Confirm the callback returns to the production app and does not open a Vercel-protected preview.
